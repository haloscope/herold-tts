## Phase 0 — Preparation

```bash
cd ~/herold
git clone https://git.lab/dataport/herold-tts.git && cd herold-tts
# If an older checkout exists, preserve the HF cache to avoid another 3.8 GB download:
#   cp -r ~/herold/herold-tts.alt/data/hf-cache/* data/hf-cache/ 2>/dev/null
df -h ~
docker images | grep herold
docker image prune -f
mkdir -p data/audition data/renders data/final data/hf-cache
sudo chown -R 999:999 data/
```

- [ ] Checkout is on the current `main` (a `git log -1` commit with timestamp 12:00 UTC).
- [ ] ✅ At least **40 GB free disk space** on the target filesystem.
- [ ] ✅ Signature voice present: `ls data/audition/reference_design_de.wav`.
- [ ] Images from the old ZIP-transfer era (15.3 GB / 9.8 GB) removed or accounted for.

## Phase 1 — Retrieve images from the registry

```bash
docker login registry.git.lab        # Password: PAT with read_registry
docker pull registry.git.lab/dataport/herold-tts/gpu:latest
docker tag  registry.git.lab/dataport/herold-tts/gpu:latest herold-tts:latest
docker pull registry.git.lab/dataport/herold-tts/cpu:latest
docker tag  registry.git.lab/dataport/herold-tts/cpu:latest herold-tts:cpu
```

**Why retag the images?** Docker Compose refers to local image names `herold-tts:latest` and `herold-tts:cpu`. Without these aliases, `compose up` may use an older local image or silently build again.

- [ ] ✅ Both pulls succeed without `denied` (otherwise check the token, project role and `docs/DEPLOYMENT.md` → CI/CD).

## Phase 2 — GPU test (port 8000)

```bash
docker compose up -d
docker ps --filter name=herold       # Initially "health: starting"; then "(healthy)" after 1–3 min
curl -s localhost:8000/api/status
```

- [ ] ✅ Container reaches **`(healthy)`** (validates the v0.4.1 HTTP health check).
- [ ] ✅ `/api/status` reports `"version":"0.4.3"` and `"device":"cuda:0"`.
      If it reports `cpu`, `docker info | grep -i runtime` must list `nvidia`.
      Otherwise run `sudo nvidia-ctk runtime configure --runtime=docker && sudo systemctl restart docker`.

**End-to-end demo test:** Open `http://hive:8000/` in a browser (redirects to `/demo/`).

1. Enter ID `gputest` (the default sample texts can remain), then click **Render**.
2. On first use, the model downloads approximately 3.8 GB into `data/hf-cache/`. Monitor progress using `docker logs -f herold-tts-gpu`.
3. Play all three generated audio files.
4. Click **Convert** to create M4A/MP3 files in the file list.

- [ ] ✅ All three WAV files play (`gputest_en`, `gputest_de`, `gputest_multiversion`). Voice matches the signature reference; English retains a German accent. The combined version is EN + 2-second pause + DE.
- [ ] ✅ Conversion generates `.m4a` and `.mp3`, and downloads work.
- [ ] Measured total render wall-clock time (job duration or logs): ________
- [ ] Measured VRAM during rendering (`nvidia-smi`): ________

*For `[Errno 5]` during model loading, see `docs/DEPLOYMENT.md` → Troubleshooting ("Errno 5").*

## Phase 4 — CPU test (port 8001; can run alongside the GPU container)

```bash
docker compose --profile cpu up -d herold-tts-cpu   # IMPORTANT: specify the service,
                                                    # otherwise the GPU service also starts
docker ps --filter name=herold
curl -s localhost:8001/api/status
```

- [ ] ✅ CPU container becomes `(healthy)`; `/api/status` reports `"device":"cpu"` and `"version":"0.4.3"`.

Open `http://hive:8001/`; render with ID `cputest`. Expect slower execution (the CPU image deliberately limits inference to four threads, as fixed in v0.3.3). The model should come from the same `data/hf-cache`, without a second download.

- [ ] ✅ Three playable files with a voice consistent with the GPU version. Minor prosody differences are expected; bf16 on CPU and GPU is not bit-identical.
