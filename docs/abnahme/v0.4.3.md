## Phase 0 — Vorbereitung

```bash
cd ~/herold
git clone https://git.lab/dataport/herold-tts.git && cd herold-tts
# Falls altes Verzeichnis existiert: HF-Cache retten (spart 3,8 GB Download):
#   cp -r ~/herold/herold-tts.alt/data/hf-cache/* data/hf-cache/ 2>/dev/null
df -h ~
docker images | grep herold
docker image prune -f
mkdir -p data/audition data/renders data/final data/hf-cache
sudo chown -R 999:999 data/
```

- [ ] Checkout auf aktuellem `main` (`git log -1` zeigt einen Commit mit Zeitstempel 12:00 UTC)
- [ ] ✅ Mindestens **40 GB frei** auf dem Ziel-Dateisystem
- [ ] ✅ Signature-Stimme vorhanden: `ls data/audition/reference_design_de.wav`
- [ ] Alte Images der Zip-Ära (15,3 GB / 9,8 GB) entfernt bzw. bekannt

## Phase 1 — Images aus der Registry

```bash
docker login registry.git.lab        # Passwort: PAT mit read_registry
docker pull registry.git.lab/dataport/herold-tts/gpu:latest
docker tag  registry.git.lab/dataport/herold-tts/gpu:latest herold-tts:latest
docker pull registry.git.lab/dataport/herold-tts/cpu:latest
docker tag  registry.git.lab/dataport/herold-tts/cpu:latest herold-tts:cpu
```

**Warum das `docker tag`:** Compose referenziert die lokalen Namen `herold-tts:latest`/`:cpu`;
ohne Umhängen würde `compose up` still ein lokales (ggf. altes) Image nutzen oder neu bauen.

- [ ] ✅ Beide Pulls ohne `denied` (sonst: Token/Rolle prüfen, docs/DEPLOYMENT.md → CI/CD)

## Phase 2 — GPU-Test (Port 8000)

```bash
docker compose up -d
docker ps --filter name=herold       # erst "health: starting", nach 1–3 min "(healthy)"
curl -s localhost:8000/api/status
```

- [ ] ✅ Container wird **`(healthy)`** (testet den v0.4.1-HTTP-Healthcheck)
- [ ] ✅ `/api/status`: `"version":"0.4.3"` **und** `"device":"cuda:0"`
      (steht dort `cpu` → `docker info | grep -i runtime` muss `nvidia` listen;
      sonst `sudo nvidia-ctk runtime configure --runtime=docker && sudo systemctl restart docker`)

**E2E über die Demo-Seite** — Browser: `http://hive:8000/` (leitet auf `/demo/` um):

1. ID `gputest` eintragen (Texte können bleiben) → **Rendern**
2. Erster Lauf lädt einmalig ~3,8 GB Modell nach `data/hf-cache/`
   (Fortschritt: `docker logs -f herold-tts-gpu`)
3. → drei Audio-Player, **anhören**
4. **Konvertieren** → m4a/mp3 in der Dateiliste

- [ ] ✅ Drei WAVs abspielbar (`gputest_en`, `gputest_de`, `gputest_multiversion`),
      Signature-Stimme, EN mit deutschem Akzent, Multiversion = EN + 2 s Pause + DE
- [ ] ✅ Konvertierung liefert `.m4a` + `.mp3`, Downloads funktionieren
- [ ] Messwert — Render-Wallzeit gesamt (aus Job-Dauer/Logs): ________
- [ ] Messwert — VRAM während Render (`nvidia-smi`): ________

## Phase 4 — CPU-Test (Port 8001, parallel zum GPU-Container möglich)

```bash
docker compose --profile cpu up -d herold-tts-cpu   # WICHTIG: Servicename mit angeben,
                                                    # sonst startet der GPU-Service mit
docker ps --filter name=herold
curl -s localhost:8001/api/status
```

- [ ] ✅ CPU-Container wird `(healthy)`; `/api/status`: `"device":"cpu"`, `"version":"0.4.3"`

Demo auf `http://hive:8001/`: ID `cputest`, rendern. Erwartung: deutlich langsamer
(Image drosselt bewusst auf 4 Threads, v0.3.3-Fix); Modell kommt aus demselben
`data/hf-cache` — kein zweiter Download.

- [ ] ✅ Drei Player, Stimme identisch zur GPU-Version (minimale Betonungsunterschiede
      sind normal — bf16 auf CPU/GPU ist nicht bitidentisch)
